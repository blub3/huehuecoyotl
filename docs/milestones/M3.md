# M3 Network – status

Nov 11, 2026 · built and checked on Linux (X11, NVIDIA RTX 3080, Qt 6.12)

**Gate status: not passed yet.** SMB, NFS, WebDAV and FTP libraries work end to end on Linux: in the app by keyboard, headless through the CLI, and in CI against real servers in containers. Missing for the gate:
- SFTP in the app. The backend passes its conformance test but cannot be linked into the app yet (see Deviations).
- A Windows SMB server and a real NAS. Only Samba in a container was tested, plus mDNS discovery of a NAS on the local network.
- Windows, which is still blocked on the Windows libmpv build (M0).
- FTPS and WS-Discovery (Windows hosts without mDNS).

## Scope versus SPEC 11

| M3 item | State | How it was checked |
| --- | --- | --- |
| SMB 2/3 | Done | `smb` 0.12.1 (pure Rust). One connection per source. Reads of up to 8 MiB are split into parallel 1 MiB requests. Tested against Samba. |
| NFS v3/v4.1 | Done | `nfs-rs` 0.12 with `noresvport`, so no root rights are needed. The export needs the `insecure` option. Tested against NFS-Ganesha (v4.1). |
| WebDAV | Done | `reqwest` (rustls) with PROPFIND listings and HTTP range reads. Tested against rclone. |
| FTP | Done | `suppaftp` with one long-running `RETR` per open file: sequential reads continue on it, and a seek sends `ABOR` + `REST`. Tested against vsftpd. |
| SFTP | Backend only | `russh` + `russh-sftp`. Trust on first use: the host key's SHA-256 fingerprint is stored with the source and a different key is refused. Lives in `crates/vfs-sftp`, outside the workspace. |
| Streaming to mpv | Done | `crates/stream` registers `coyotl://<source>/<path>` with `mpv_stream_cb_add_ro`. Read-ahead adapts: a seek starts with a 256 KiB read, and the read size doubles while reads stay sequential (up to 8 MiB). One chunk is prefetched in the background. Transport errors are retried with backoff (0.25 s up to 16 s, about 30 s in total), so a short outage is a pause, not an error. mpv's own demuxer cache (`cache=yes`) sits above this. |
| Keystore credentials | Done | Share passwords go to the OS keystore under `coyotl/source:<id>`, never into the database (the `source` row stores only `credential_ref`). If the keystore is unavailable, the password is kept in memory for the session and a warning is logged. |
| Reconnect handling | Done | Every backend reconnects once by itself after a transport error. A source that cannot be reached is marked offline: a badge on the Sources page, and its files stay in the library. Offline sources are probed every minute; once one answers it is marked online and rescanned. Playing a file always tries the server again. |
| Discovery | Done (mDNS) | DNS-SD browsing for `_smb`, `_nfs`, `_webdav(s)`, `_ftp` and `_sftp-ssh` (`mdns-sd`). One entry per announced service; choosing one fills in the form. |
| UI | Done | Sources → "Add network share": discovered servers, protocol, server, port, share, user, password, HTTPS for WebDAV, "Connect" (which tests the connection and lists the share), a folder picker, then "Add this folder" or "Add the whole share". Network libraries show their protocol, a display URL without credentials, and an offline state. German translation is complete. |
| Conformance suite | Done | `crates/vfs/tests/conformance.rs` runs the same checks against every backend: listing, stat, ranged reads (start, middle, across and past the end), a sequential read of the whole file compared byte for byte, typed errors for missing paths, wrong passwords and unreachable hosts, and a connection dropped mid-stream through a cutting TCP proxy (SMB, WebDAV). It runs in CI (job `protocols`). |

## Checked in the app

- Discovery found a NAS on the local network (FTP, SMB and WebDAVS).
- Samba test share: connect, folder picker, add the whole share, scan (4 files), then play a 720p H.264 test clip with hardware decoding (`nvdec`), seek and a sidecar `.srt`. Everything came over SMB.
- Pausing the Samba container and rescanning: the source shows "offline" and nothing is deleted. After unpausing and rescanning it is online again.

## Tests

- Rust: 52 tests with `COYOTL_TEST_SERVERS=1` (the network tests skip without it). New in M3:
  - the conformance suite for SMB, NFS, WebDAV and FTP, plus the dropped-connection tests;
  - `crates/core/tests/network_flow.rs`: for each protocol, a wrong password gives a typed error, then browse the share, add a folder, scan, open the movie, read the whole file through the C stream callbacks, seek, read the sidecar subtitle, and remove the library;
  - stream unit tests: URL round trip, read-ahead growth and reset, outage turned into a pause, the C callbacks;
  - share settings parsing.
- SFTP: `crates/vfs-sftp/tests/conformance.rs` (listing, ranged and sequential reads, TOFU host key, wrong password).
- Test servers: `tests/servers/up.sh` creates deterministic fixtures and starts Samba, NFS-Ganesha, rclone (WebDAV and SFTP) and vsftpd on 172.29.0.0/24.

## Deviations from the specification

- **OpenDAL dropped.** Its SFTP service runs the system `ssh` binary, and its HTTP layer requires `aws-lc`. WebDAV uses `reqwest` directly, FTP uses `suppaftp`, and SFTP uses `russh`. SPEC section 6 is updated.
- **SFTP not in the app yet.** `smb` (through `sspi`) pins pre-release RustCrypto crates (`curve25519-dalek` 5.0.0-rc.1) that conflict with `russh`. SFTP joins the workspace once `sspi` moves to released versions. The UI hides SFTP until then.
- **WS-Discovery deferred.** mDNS covers most NAS systems and Linux servers. Windows file shares without mDNS must be entered by address.
- **MSRV raised to 1.86** for trait upcasting (`Arc<dyn RemoteSource>` to `Arc<dyn Source>`).

## How to run the network tests

```bash
tests/servers/up.sh
COYOTL_TEST_SERVERS=1 COYOTL_DISABLE_KEYSTORE=1 cargo test --workspace
COYOTL_TEST_SERVERS=1 cargo test --manifest-path crates/vfs-sftp/Cargo.toml
docker compose -f tests/servers/compose.yaml down
```

CLI: `COYOTL_SHARE_PASSWORD=… coyotl-cli share-ls '{"protocol":"smb","host":"nas","share":"media","user":"me"}' /Movies`, then `library add-share` with the same JSON plus `"path"`, and `discover`.
